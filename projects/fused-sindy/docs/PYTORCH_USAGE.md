# PyTorch Usage

FusedSINDy is designed to be driven from PyTorch CUDA tensors. Python validates
tensor layout, owns streams/tensors, and passes raw device pointers into the
native C/CUDA engine.

Use:

```python
import fused_sindy as fsindy
```

The legacy import also works:

```python
import implicit_sindy as fsindy
```

## Tensor Layouts

Use row-contiguous CUDA tensors:

```text
primitive_features: float32 [num_primitive_features, rows]
targets:            float32 [num_rhs, rows]
leaf_masks:         int32   [settings, 32]
leaf_words:         int32   [settings, 32, 8]
```

Rules:

- primitive features and targets must be `float32` CUDA tensors;
- the row dimension must have stride 1;
- primitive feature count is currently capped at 32;
- target RHS count is currently capped at 32;
- `leaf_masks` and `leaf_words` must be contiguous `int32` CUDA tensors;
- each generated feature has 8 leaves.

## AST Cohorts

A cohort contains 32 generated feature shapes. The AST stores operator
structure only. It does not store primitive-column bindings or constant values.

```python
expr = fsindy.sin(fsindy.feature(0)) + 0.1 * fsindy.feature(2)
ast, mask, words = fsindy.expression_to_ast_and_leaf_settings(expr)
```

For a full cohort:

```python
asts = [ast] + [fsindy.padding_ast()] * 31
```

Large searches should generate random AST cohorts with project-specific policy,
operator weights, and scientific constraints. The built-in helpers are useful
for tests and examples, not a complete search algorithm.

## Leaf Settings

Each feature has 8 leaves. For each leaf:

- mask bit set: `leaf_words` stores a primitive feature column index;
- mask bit clear: `leaf_words` stores raw `f32` constant bits.

Pack constants with:

```python
word = fsindy.f32_constant_word(0.5)
```

Large settings tensors should usually be generated by a CUDA kernel. The
examples under `examples/` include Philox-based settings generators compiled
with `cuda.core`.

## Gram, Solve, MSE

```python
import torch
import fused_sindy as fsindy

device = "cuda"
rows = 131072
settings = 2048

primitive = torch.randn((3, rows), device=device, dtype=torch.float32).contiguous()
target = torch.randn((1, rows), device=device, dtype=torch.float32).contiguous()

asts = fsindy.random_ast_cohort(32, seed=123)
leaf_masks = torch.zeros((settings, 32), device=device, dtype=torch.int32)
leaf_words = torch.zeros((settings, 32, fsindy.NUM_INPUTS), device=device, dtype=torch.int32)

with fsindy.compile_gram_kernels(
    asts,
    kernels_per_module=4,
    worker_count=12,
) as kernels:
    train_raw = kernels.run_gram(primitive, target, leaf_masks, leaf_words)

with fsindy.RidgeSolver(device=device) as solver:
    alphas = torch.tensor([1.0e-8, 1.0e-6, 1.0e-4], device=device, dtype=torch.float32)
    thresholds = torch.tensor([1.0e-4, 1.0e-3, 1.0e-2], device=device, dtype=torch.float32)
    solved = solver.solve_stlsq(train_raw, alphas, thresholds, row_count=rows)
```

For validation:

```python
validation_raw = kernels.run_gram(validation_primitive, validation_target, leaf_masks, leaf_words)
mse = solver.score_validation_mse(
    validation_raw,
    solved,
    validation_row_count=validation_primitive.shape[1],
)
```

The solve and MSE calls enqueue CUDA work on the current PyTorch stream by
default. The API does not force a host synchronize; synchronize only when the
caller needs results on the host.

## Column Materialization Helpers

The main path avoids materializing generated features. For debugging and
reference checks, the Python API also exposes:

```python
fsindy.compile_column_kernels(...)
fsindy.compile_single_ast_column_kernels(...)
```

These kernels write generated feature columns to tensors so tests can compare
the fused Gram path against explicit columns.

## Context And Lifetime

The Python handles are context managers:

```python
with fsindy.compile_gram_kernels(asts) as kernels:
    raw = kernels.run_gram(...)
```

Closing a handle unloads modules and releases native compiler/module state.
CUDA tensors and streams remain owned by PyTorch.

## Common Pitfalls

| Pitfall | Symptom | Fix |
| --- | --- | --- |
| CPU tensor passed to native path | Runtime validation error | Move inputs to CUDA. |
| Float64 primitive data | Dtype validation error | Convert to `float32`. |
| Row dimension not contiguous | Stride validation error | Use `.contiguous()` after stacking/transposing. |
| Too few settings per cohort | Compile dominates | Increase settings per compiled structure. |
| Too few rows | Machinery overhead dominates | Use a simple PyTorch/materialized baseline. |
| Validation reused too aggressively | Great validation MSE, poor generalization | Keep final test data untouched and rotate splits. |
