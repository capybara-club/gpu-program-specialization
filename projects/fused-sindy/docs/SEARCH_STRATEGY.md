# Search Strategy

FusedSINDy accelerates one part of sparse equation discovery: evaluating many
generated feature cohorts and scoring sparse linear models from their
Gram/statistics. It does not automatically provide a complete scientific search
strategy.

## Practical Loop

```text
1. Generate random or guided AST cohorts.
2. Generate many runtime settings per cohort on the GPU.
3. Compile AST cohorts to cubins on CPU worker threads.
4. Launch fused Gram kernels on training data.
5. Solve ridge/STLSQ sweeps.
6. Launch Gram kernels on validation data.
7. Score validation MSE.
8. Keep sparse, low-MSE candidates.
9. Mutate, merge, or replace weak cohort entries.
```

The key amortization rule is:

```text
compile structure once, evaluate many settings
```

## Settings Generation

Runtime settings choose primitive-column leaves and constants. This is where a
large amount of search can happen without recompiling AST structure.

Useful policies:

- random primitive-column bindings;
- constants from small physical sets such as `0`, `1`, `0.5`, `2`;
- constants from wider continuous ranges;
- mutation around constants from successful candidates;
- operator-specific priors that avoid invalid domains;
- fixed bindings for active inherited features plus random settings for new
  feature slots.

Large settings tensors should be generated by a CUDA kernel. This avoids Python
loop overhead and lets an LLM produce a custom settings generator for each
problem family.

## STLSQ During Search

STLSQ should usually be part of the search loop. The 32x32 solve is much cheaper
than feature generation, so sparse support and validation MSE can be computed
for every settings batch rather than only after a dense ridge prefilter.

Useful per-candidate outputs:

```text
alpha
threshold
active feature mask
active feature count
beta vector
train/validation MSE
primitive leaf bindings
constant values
AST operation structure
```

## MAP-Elites Style Archive

A practical archive unit is the solved sparse phenotype plus its source cohort:

```text
genome:
  32 AST feature slots
  best leaf masks/words for the winning setting

phenotype:
  active mask after STLSQ
  beta vector
  alpha/threshold
  validation MSE
```

Simple archive axes:

```text
active feature count
operator family or nonlinear count
derivative-term count
constant usage
validation MSE bucket
robustness across seeds/settings
```

For crossover, copy active features and their winning settings from parents,
then fill inactive slots with new random or mutated ASTs and fresh settings.
This prevents the archive from repeatedly recombining inactive "dark" features.

## Avoiding Duplicate Elites

Two cohorts can look different but solve to the same effective model. Useful
deduplication signals include:

- active feature expressions after STLSQ;
- beta vector similarity;
- validation prediction similarity;
- residual similarity on a held-out probe set;
- primitive/operator family overlap.

Residual similarity is a bookkeeping tool outside the CUDA kernel. It asks
whether two solved cohorts leave nearly the same error pattern, which means
crossover between them may add little diversity.

## LLM-Assisted Use

This project is deliberately friendly to LLM-generated glue code:

- the public C API is explicit and C99-shaped;
- ASTs and settings are plain arrays;
- the Python API validates tensor shapes;
- custom settings kernels can be generated with `cuda.core`;
- examples are short enough for an LLM to adapt.

A useful LLM prompt should include:

```text
primitive feature names and tensor layout
target definitions
allowed unary/binary ops
row counts and validation split
settings count per cohort
search budget
desired MAP-Elites axes
whether constants are allowed and from what ranges
```

## Acceptance Discipline

High throughput makes overfitting easier. Before accepting an equation:

- keep a final untouched test split;
- check multiple seeds or trajectories;
- inspect active expressions and coefficients;
- report alpha, threshold, MSE, and normalization convention;
- compare against known equations on synthetic data when possible.
