# Original settings versus current toggles — 2026-09-19

Later that day, [selector reuse](report-selector-reuse-20260919.md) improved the
shared-choice fixture. That implementation is now an archived experiment; the
default writer was restored to the version measured here, for arbitrary ASTs
with transient selector results.

**The toggle rewrite preserves the evaluated results, but its execution speed is workload-dependent.** Packed ASTs with common leaf choices regressed; diverse choices and short datasets benefit from the new path. The earlier 165 → 53 register result compared two toggle implementations and did not establish a speedup over original settings.

Rack1 GPU 1: RTX 5080, 84 SMs, CUDA 13.1, driver 595.91.07. Settings: untouched Secant 0.1 sources from `7c77c3e`. Toggles: current 0.3 shared-bank implementation. One backend runs at a time on the same GPU; execution order alternates.

All **32 paired cases passed**. All **14,811,136 corresponding scores were byte-for-byte identical**. Every score was also checked against an independent CPU oracle; the maximum scaled error was 9.25e-06. Signed prediction checks at the first row covered every AST/configuration; maximum scaled error was 8.09e-07. The acceptance threshold for both checks was 2e-5. No failed or unsupported cases were dropped.

## Execution-engine throughput

Rates below are **billions of row evaluations per second**, including squared-error accumulation and tile reduction. One row evaluation is one AST × one bank/permutation configuration × one row. Kernels are prepared and resident, launched with the same CUDA graph harness, and timed using CUDA events. Seven samples follow two warmups; tables use medians. Source generation, NVRTC, transfers, output clearing, CPU validation, and module loading are excluded from this metric. The native launch geometry of each implementation is retained.

The main matrix uses 128 AST occurrences, 8,192 rows, 16 coefficient banks × 256 permutations = 4,096 configurations/AST, eight state columns, eight constants, one target, 128-thread blocks, and 128-row tiles. Arithmetic ASTs have eight leaves and seven add/subtract/multiply nodes; sine ASTs add four sine nodes. All ASTs use the same bank values and permutation bits. Data repeat 64 distinct rows to make complete CPU validation inexpensive; the GPU evaluates every row.

## What explains the difference

1. **Repeated selector work.** The original settings kernel resolves its shared dynamic leaves once per row and reuses them across packed ASTs. The new writer currently repeats each AST’s selections. Disassembly of the shared eight-AST arithmetic case confirms **112 adjacent predicate-test/FSEL pairs per row** in the toggle patch: 224 selection instructions. The original kernel has eight predicate-producing mask tests and nine shared loads (eight leaves plus target), with no equivalent repeated FSEL sequence. Both native writers use the same conservative 12-cycle ALU stall. This supports repeated selection work as the primary compiler optimization target; it is not a cycle-accurate attribution of every measured difference.

2. **Launch coverage.** The old native settings CTA loops over settings. The new shape distributes configurations across grid.y as well as row tiles. At 256 rows the original geometry offers very few CTAs per function; toggles expose much more parallel work. At large row counts this advantage shrinks. Resource-based occupancy limits were recorded; achieved occupancy was not profiled.

3. **Dynamic-slot register cost.** The settings shape carries runtime words, addresses, predicates, and values for its dynamic slots. With 32 slots its resource cost grows considerably; current toggle registers stay near 53 at eight-AST packing. The diverse sine workload improves despite repeated selectors.

4. **Maximum packing is not automatically best.** At 32 ASTs the current template jumps to 168 registers and uses local memory. That is a separate NVRTC/scaffold tuning issue, and the table includes it rather than hiding the case.

## Next changes to investigate

- Selected-leaf reuse was investigated and archived; do not depend on shared selectors or similarity-based packing in the default writer.
- Move constant-only selections outside the row loop where the template permits it.
- Profile instruction issue/dependencies and actual occupancy before changing conservative SASS scheduling.
- Tune the 32-AST scaffold and keep this paired benchmark as a performance regression gate.

No production kernel was changed during this comparison. The slowdown remains open. Correctness is validated for these fixtures; throughput conclusions do not cover every AST size, operator mixture, GPU architecture, or a retuned historical settings implementation.
